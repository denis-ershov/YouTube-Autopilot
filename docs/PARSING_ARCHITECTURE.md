# Архитектура Парсинга и Взаимодействия с YouTube DOM

## 1. Обзор
Документ описывает архитектурный слой расширения **YouTube Autopilot**, отвечающий за работу с динамическим интерфейсом YouTube, отслеживание событий HTML5 плеера, детекцию SPA-навигации, алгоритм расчета реально просмотренного времени (`Real Watch Tracking`) и внедрение инлайн-интерфейсов (Overlay UI).

---

## 2. Изолированный слой YouTube Adapter (`src/youtube/`)

Для защиты ядра системы от изменений DOM-верстки YouTube все взаимодействия с веб-страницей изолированы в отдельном пакете `src/youtube/`:

```text
src/youtube/
├── selectors.ts     # Изолированные CSS-селекторы элемента плеера, метаданных и кнопок
├── navigation.ts    # Детектор SPA-навигации (yt-navigate-finish, URL mutation)
├── player.ts        # PlayerObserver подписки на события HTML5 Video Element
├── actions.ts       # Выполнитель DOM-действий с retry policy (Like, Watch Later, Hide)
├── overlay.ts       # Инлайн-индикатор прогресса в плеере YouTube
└── adapter.ts       # Фасад YouTubeAdapter для обращения из Content Script
```

---

## 3. Отслеживание SPA Навигации

YouTube является Single Page Application (SPA), поэтому перезагрузки страницы при переходе между видео не происходит.

### Поток детекции:
1. Регистрация кастомного события YouTube `yt-navigate-finish`.
2. Регистрация `MutationObserver` для отслеживания изменения `location.href`.
3. Парсинг `videoId` из параметров URL (`?v=XXXXXX` или `/shorts/XXXXXX`).
4. При смене `videoId`:
   - Завершение текущего сеанса отслеживания в `RealWatchTracker`.
   - Сохранение накопленных интервалов в `IndexedDB`.
   - Инициализация нового экземпляра отслеживания для нового `videoId`.

## 4. Инлайн-Индикатор Плеера (Player Overlay UI)

Для предоставления пользователю визуального контроля расширение внедряет компактный виджет над/рядом с элементами управления плеером YouTube (`.ytp-right-controls` или `#above-the-fold`):

- **Показывает:** % реального просмотра, реально просмотренные минуты, статус следующего автоматического действия (напр. `❤️ Like at 90%`).
- **Стилизация:** Не перекрывает стандартные элементы управления плеером, отключается в настройках.

---

## 5. Retry Policy для DOM-действий

При выполнении автоматических действий в динамическом DOM YouTube (напр. клик по кнопке Like или удаление из Watch Later):
1. Попытка 1: Поиск элемента по селектору.
2. В случае неудачи: Повтор через 2 секунды (Попытка 2).
3. В случае повторной неудачи: Повтор через 5 секунд (Попытка 3).
4. При исчерпании 3 попыток действие помечается статусом `FAILED` с сохранением причины ошибки в логе исполнения (`rule_executions`).

---

## 6. Алгоритм Real Watch Tracking

1. `PlayerObserver` слушает события плеера: `play`, `pause`, `timeupdate`, `seeking`, `seeked`, `ended`.
2. При `play` начинается текущий интервал `[startTime, currentTime]`.
3. При каждом `timeupdate` (без скачка перемотки) интервал расширяется.
4. При `seeking` текущий интервал фиксируется и закрывается. Скачок игнорируется.
5. Интервалы объединяются функциями слияния (Interval Merging):
   ```text
   [0, 100] + [90, 200] => [0, 200]
   ```
6. Фактически просмотренные секунды: `sum(interval.end - interval.start)`.
7. Процент просмотра: `(watchedSeconds / duration) * 100`.
