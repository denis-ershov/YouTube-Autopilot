# Архитектура Парсинга и Взаимодействия с YouTube DOM

## 1. Обзор
Документ описывает архитектурный слой расширения **YouTube Autopilot**, отвечающий за работу с динамическим интерфейсом YouTube, отслеживание событий HTML5 плеера, детекцию SPA-навигации, устойчивый алгоритм расчета реально просмотренного времени (`Real Watch Tracking`), гидратацию состояния и внедрение инлайн-интерфейсов (Overlay UI).

---

## 2. Изолированный слой YouTube Adapter (`src/youtube/`)

Для защиты ядра системы от изменений DOM-верстки YouTube все взаимодействия с веб-страницей изолированы в отдельном пакете `src/youtube/`:

```text
src/youtube/
├── selectors.ts     # Изолированные CSS-селекторы элемента плеера, метаданных и кнопок
├── navigation.ts    # Детектор SPA-навигации (yt-navigate-finish, URL mutation) с защитой от race conditions
├── player.ts        # PlayerObserver с реактивным переподключением через MutationObserver
├── url.ts           # Разбор Video ID из URL (общий для Content Script и Popup)
├── actions.ts       # Выполнитель DOM-действий с retry policy (Like, Save, Hide)
├── overlay.ts       # Инлайн-индикатор прогресса в плеере YouTube
├── approvalBanner.ts# Карточка подтверждения действия (режим approval)
├── icons.ts         # SVG-иконки внедряемого UI: знак бренда и сердце
└── adapter.ts       # Фасад YouTubeAdapter для обращения из Content Script
```

---

## 3. Отслеживание SPA Навигации и Жизненный Цикл

YouTube является Single Page Application (SPA), поэтому перезагрузки страницы при переходе между видео не происходит.

### Поток детекции:
1. Фиксация `videoId` из параметров URL (`?v=XXXXXX` или `/shorts/XXXXXX`).
2. Первичная инициализация с немедленным присвоением `this.lastVideoId = currentId` для устранения race conditions при последующем вызове `yt-navigate-finish`.
3. Регистрация кастомного события YouTube `yt-navigate-finish` и резервного `MutationObserver` для отслеживания изменения `location.href`.
4. При смене `videoId`:
   - Принудительная отправка (flush) накопленного прогресса предыдущего видео на Background Service Worker.
   - Сброс текущего трекера: события плеера в окне ожидания (800 мс) не засчитываются ни старому, ни новому видео.
   - Очистка предыдущего таймера навигации (`clearTimeout(navTimeout)`).
   - Запрос к фоновому Service Worker (`VIDEO_STARTED`) для получения сохраненных ранее данных (гидратация интервалов и процентов).
   - Инициализация `RealWatchTracker` с восстановленными интервалами `initialIntervals`.
   - Немедленное обновление оверлея плеера восстановленным значением прогресса.

## 4. Реактивный Наблюдатель Плеера (`PlayerObserver`)

YouTube динамически монтирует, заменяет и пересоздает тег `<video>` при смене качества, форматов, показе рекламы и переходах между Shorts и обычными видео.

### Механизмы устойчивости:
1. **Реактивный MutationObserver:** следит за появлением и заменой `<video>` в DOM дереве и автоматически переподключает слушатели событий к новому узлу.
2. **Heartbeat-проверка:** интервал (1 сек) проверяет наличие и валидность ссылки на элемент `<video>`.
3. **Поддержка Shorts:** селекторы плеера адаптированы как для стандартного плеера (`#movie_player video`), так и для Shorts (`ytd-reel-video-renderer[is-active] video`).
4. **Слушаемые события:** `play`, `pause`, `timeupdate`, `seeking`, `seeked`, `ended`, `ratechange`, `durationchange`, `loadedmetadata`.
5. **Защита от NaN:** безопасная нормализация `currentTime` и `duration` с защитой от значений `NaN` и отрицательных чисел до загрузки метаданных.

## 5. Инлайн-Индикатор Плеера (Player Overlay UI)

Для предоставления пользователю визуального контроля расширение внедряет компактный виджет над/рядом с элементами управления плеером YouTube (`.ytp-left-controls` / `.ytp-time-display`):

- **Стандарты оформления (UI/UX Pro Max) и безопасность (Mozilla AMO):**
  - Полный отказ от эмодзи в роли структурных иконок: используются векторные SVG-иконки.
  - Соответствие контраста стандартам WCAG (≥4.5:1).
  - Плавные микро-анимации перехода (150–200ms) с сохранением стабильности геометрии плеера (без layout shift).
  - **Безопасное DOM-построение:** полный отказ от `innerHTML` в пользу `document.createElement`, `document.createTextNode`, `setAttribute` и `textContent`. Элементы капсулы и поповера создаются один раз при инициализации, а при тиках обновляются только текстовые значения и ширина прогресс-бара. Это полностью исключает риски XSS, утечки памяти и удовлетворяет строгим требованиям валидации Mozilla AMO.
- **Показывает:** % просмотра по активному режиму (`real` / `position` / `hybrid`), учтённое время и следующее действие с порогом пользователя (`Settings.defaultThreshold`).
- **Знак бренда:** монохромная версия логотипа (кольцо прогресса + Play + маркер порога) из `src/youtube/icons.ts`; та же иконка используется в карточке подтверждения.

### Карточка подтверждения (`approvalBanner.ts`)
- Одновременно показывается одна карточка; остальные запросы ждут в очереди Content Script.
- «Разрешить» выполняет действие, «Пропустить», `Escape` и таймаут 10 с — отказ: действие не повторяется для этого видео до перезагрузки вкладки.
- `role="alertdialog"`, кнопки не меньше 32 px по высоте внутри плотного UI плеера.

## 6. Алгоритм Real Watch Tracking с учетом физического времени и скорости

Стандартный алгоритм был модернизирован для корректной работы в фоновых вкладках браузера и при ускоренном воспроизведении:

1. `RealWatchTracker` фиксирует физическое время (`lastWallTime = Date.now()`) и медиа-время плеера (`lastMediaTime`).
2. При каждом тике вычисляется:
   - Физически прошедшее время: `wallDeltaSec = (Date.now() - lastWallTime) / 1000`.
   - Ожидаемый прогресс медиа: `expectedMediaDelta = wallDeltaSec * playbackRate`.
   - Фактический прогресс медиа: `mediaDelta = currentTime - lastMediaTime`.
3. **Детекция перемотки/скачка:**
   - Скачок назад: `mediaDelta < -0.5`.
   - Скачок вперед без воспроизведения: `mediaDelta - expectedMediaDelta > max(3.0, 2.5 * playbackRate)`.
   - При обнаружении скачка: текущий интервал закрывается и сохраняется, а новый интервал начинается с точки приземления `[currentTime, currentTime]`.
4. **Фоновые вкладки и ускорение:** если браузер троттлит `timeupdate` до 3 секунд, `wallDeltaSec` также равен ~3 секундам, что соответствует `expectedMediaDelta`. Скачок не фиксируется, и время просмотра непрерывно учитывается.
5. **Явные события перемотки:** события `seeking` вызывают `onSeekStart()` с фиксацией интервала, а `seeked` вызывает `onSeekEnd(newTime)`.
6. **Отложенное получение длительности:** если `duration == 0` в момент старта видео, просмотр продолжает накапливаться в интервалах, а процент мгновенно пересчитывается при вызове `setDuration(duration)`.
7. **Интервалы объединяются слиянием (Interval Merging):**
   ```text
   [0, 100] + [95, 200] => [0, 200]
   ```
8. Фактически просмотренные секунды: `sum(max(0, interval.end - interval.start))`.
9. Процент просмотра: `min(100, (watchedSeconds / duration) * 100)`.

## 7. Троттлинг IPC и Оптимизация Производительности

Для предотвращения флуда сообщениями между Content Script и Background Service Worker:
1. `PROGRESS_UPDATE` отправляется не чаще 1 раза в 2 секунды (и немедленно при `pause`, `ended`, переключении видео или `beforeunload`).
2. Настройки (`getSettings`) и правила (`getRules`) кэшируются в памяти Content Script и обновляются реактивно по событию `chrome.storage.onChanged`, исключая 5 обращений к хранилищу в секунду.
3. Проверка правил автоматизации выполняется с интервалом 2 секунды.

## 8. Режимы Отслеживания Просмотра (Real vs Position vs Hybrid)

Для гибкой настройки пользовательского опыта в систему заложены три режима отслеживания (`WatchTrackingMode`):

### 1. Честное время (`real`)
- **Принцип:** Суммируются только непрерывные секунды воспроизведения (объединенные интервалы).
- **Поведение при перемотке:** Скачки вперед не добавляют фиктивного времени.
- **Использование:** Для пользователей, желающих ставить лайки и выполнять автоматизацию только при добросовестном, внимательном просмотре.

### 2. С учетом перемотки / Позиция ползунка (`position`)
- **Принцип:** Отслеживается максимальная отметка воспроизведения на шкале времени (`maxPosition = Math.max(maxPosition, currentTime)`).
- **Поведение при перемотке:** Если пользователь посмотрел начало, перемотал в середину и затем в конец, и ползунок пересек 90% длительности видео, процент просмотра фиксируется как `≥ 90%`.
- **Использование:** Позволяет ставить автолайк и завершать автоматизации при беглом ознакомлении с видео и перемотках.

### 3. Гибридный режим (`hybrid`)
- **Принцип:** Комбинация защиты от случайных кликов и удобства перемотки.
- **Условие:** Ползунок плеера пересек порог (`maxPositionPercent >= 90%`) **И** при этом реально просмотрено не менее 15% длительности видео (или 30 секунд).
- **Использование:** Исключает случайный клик в конец видео при случайном открытии вкладки, но поощряет содержательный просмотр с перемотками.

## 9. Соответствие Стандартам Безопасности Браузеров (Mozilla AMO & Chrome Web Store)

Для успешной публикации и автоматической проверки в каталогах расширений (`addons.mozilla.org` и `Chrome Web Store`) в проекте реализованы строгие меры безопасности:

1. **Декларация согласия на сбор данных (`data_collection_permissions`) и `strict_min_version`:**
   - Начиная с ноября 2025 года Mozilla AMO требует обязательного наличия ключа `browser_specific_settings.gecko.data_collection_permissions` в `manifest.json`.
   - В `wxt.config.ts` задекларировано: `"data_collection_permissions": { "required": ["none"] }`, подтверждая, что расширение не собирает и не передает данные пользователей на внешние сервера.
   - Минимальная версия Gecko установлена в `strict_min_version: "142.0"`, что полностью удовлетворяет требованиям совместимости с Firefox Desktop (с версии 140) и Firefox for Android (с версии 142) и исключает предупреждения манифеста.
2. **Полное исключение Unsafe innerHTML (включая зависимости):**
   - Ни в одном скрипте контента или компоненте оверлея не используется присвоение в `innerHTML`.
   - Все узлы DOM и векторные SVG строятся нативно через `document.createElementNS` и `document.createElement`, а текстовые узлы выводятся через `textContent` и `createTextNode`.
   - Дополнительно настроен Vite-плагин `amo-sanitize-innerhtml`, заменяющий неиспользуемые операции `.innerHTML=` в коде `react-dom` на безопасные обращения к `textContent`.
   - Это гарантирует 0 ошибок и 0 предупреждений в валидаторе AMO и защищает пользователя от любых векторов XSS.
3. **Локальная изоляция данных:**
   - Все пользовательские правила, статистика и история хранятся локально в IndexedDB и `chrome.storage.local`. Сетевые запросы к внешним API отсутствуют.

## 10. Известные ограничения

| Ограничение | Последствие | Статус |
| :--- | :--- | :--- |
| `REMOVE_FROM_WATCH_LATER` лишь открывает диалог «Сохранить» и не снимает отметку «Смотреть позже» | Действие не выполняет обещанное | Скрыто из UI (форма правил, пресеты, онбординг); требуется отдельная реализация |
| `VideoRecord.source` не определяется (нет разбора `list=WL` и т.п.) | Условие `SOURCE` и пресет «Очищать «Смотреть позже»» никогда не срабатывают | Пресет остаётся в хранилище для совместимости, но неактивен по факту |
| Селектор `SAVE_BUTTON` опирается на `aria-label` («Save» / «Сохранить») | На других языках интерфейса YouTube кнопка не найдётся | Требует селектора, не зависящего от языка |
| Резервный `MutationObserver` навигации следит за всем `document.body` | Дополнительная нагрузка на очень динамичных страницах | Основной сигнал — `yt-navigate-finish`; оптимизацию стоит делать по замерам |
| `IS_SHORT` определяется по URL `/shorts/` | Shorts, открытые как обычное видео (`/watch`), считаются обычными | Осознанное упрощение |
