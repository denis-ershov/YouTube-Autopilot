## 🛠️ С чего начать

1. **Создайте Fork** репозитория на GitHub.
2. **Клонируйте форк локально**:
   ```bash
   git clone https://github.com/<ваш-аккаунт>/YouTube-Autopilot.git
   cd YouTube-Autopilot
   ```
3. **Установите зависимости**:
   ```bash
   npm install
   ```
4. **Запустите dev-сервер с поддержкой HMR**:
   ```bash
   npm run dev          # Chrome
   npm run dev:firefox  # Firefox
   ```

## 📐 Правила и стандарты разработки

### 1. Стандарты кода
- **TypeScript**: Включен строгий режим (`strict: true`). Любой код обязан проходить проверку типов (`npm run compile`).
- **React 19 и хуки**: Используйте функциональные компоненты и современные паттерны React.
- **Tailwind CSS**: Используйте дизайн-токены и адаптивные утилитарные классы.
- **Политика нулевого `innerHTML`**: В целях безопасности и соответствия строгим требованиям каталогов расширений (Mozilla AMO) **запрещено** использование `innerHTML` или `dangerouslySetInnerHTML`. Формируйте узлы DOM безопасно с помощью JSX или нативных вызовов `document.createElement` и `document.createTextNode`.

### 2. Локализация (i18n)
- Все пользовательские тексты должны выводиться через модуль локализации `src/i18n`.
- При добавлении нового ключа обязательно добавляйте его как в `src/locales/ru.json`, так и в `src/locales/en.json`, сохраняя 100% паритет словарей.

### 3. Документация и Changelog
- Все значимые изменения обязательно фиксируются в `docs/CHANGELOG.md` с указанием:
  - Даты и версии;
  - Списка измененных файлов;
  - Описания изменений и их обоснования.
- При изменении архитектуры или схемы хранения данных обновляйте соответствующий документ в `docs/`.

## 🧪 Проверка перед отправкой Pull Request

Перед созданием Pull Request обязательно запустите следующие команды:

```bash
# 1. Проверка типов TypeScript
npm run compile

# 2. Сборка для Chrome и Firefox
npm run build:all

# 3. Упаковка расширения в архивы
npm run zip:all
```
Убедитесь, что все команды завершаются с кодом возврата `0`.

## 📄 Процесс отправки Pull Request

1. Создайте отдельную ветку (`git checkout -b feature/название-функции` или `fix/описание-исправления`).
2. Зафиксируйте изменения понятными коммитами.
3. Отправьте изменения в свой форк и создайте Pull Request в ветку `main` основного репозитория.
4. В описании PR укажите, какую проблему решает изменение и как его протестировать.
